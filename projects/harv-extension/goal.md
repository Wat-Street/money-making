# CP-OPS-HG Testing Ladder Goal

## Objective

Implement a reproducible CP-OPS-HG testing ladder for the existing HAR/realized-volatility repository while preserving the current 5-minute realized-volatility data, 10-asset universe, target alignment, expanding-window forecast origins, and prior conditional-regime definitions wherever possible.

The locked model ladder is:

1. HAR-RV
2. Fresh CP
3. Raw PM
4. Raw CP+PM
5. CP + OPS-R
6. CP + ridge OPS-R
7. CP + LRPM
8. CP + recent slope
9. CP + Haar shape
10. CP + OPS-C
11. CP + ridge OPS-C
12. CP + gated ridge OPS-C
13. CP-OPS-HG
14. Random residues placebo
15. Shuffled lag PM placebo
16. Random gate placebo
17. Ridge AR(22)
18. CP-OPS-K, implemented if feasible and otherwise cleanly scaffolded

## Repository Findings

- Existing CP+PM incremental script: `outputs/cp_pm_incremental_tests/scripts/run_cp_pm_incremental_tests.py`.
- Existing data loading: `code/utils/data_utils.py`.
- Existing CP/PM feature construction: `code/utils/models_utils.py`.
- Existing expanding-window alignment: `fit_and_predict_extended` in `data_utils.py`, with a faster normal-equation implementation in the CP+PM incremental script.
- Existing conditional buckets: `define_conditions` in the CP+PM incremental script.
- Prior CP+PM output folder: `outputs/cp_pm_incremental_tests/`.
- Prior 10-asset universe: `AAPL, AMZN, EEM, FXI, GLD, GOOGL, HYG, QQQ, SPY, TLT`.
- Prior fresh CP recomputation validates against saved `run_results/current_intraday/predictions` CP predictions for all 10 assets.

## Compatibility Decision

The locked spec defines CP as explicit disjoint lag blocks and OPS features as orthogonal to that CP block space. The repository's current CP benchmark is `contig_prime_modulo`, a rolling prime-phase local volatility feature system, not an explicit disjoint block projection.

Implementation policy:

- Preserve the repository's existing CP as the fresh benchmark and for raw CP+PM reproduction.
- Build CP-orthogonal OPS/shape weights against the spec fallback lag blocks:
  - `B1 = {1, 2, 3}`
  - `B2 = {4, 5, 6, 7, 8}`
  - `B3 = {9, 10, 11, 12, 13, 14}`
  - `B4 = {15, 16, 17, 18, 19, 20, 21, 22}`
- Record this compatibility choice in metadata, feature manifests, and the generated README.

## Implementation Plan

- Add standalone runner: `outputs/cp_ops_hg_tests/scripts/run_cp_ops_hg_tests.py`.
- Default output folder: `outputs/cp_ops_hg_tests/`.
- Preserve all existing folders, especially `outputs/cp_pm_incremental_tests/`.
- Add CLI options for:
  - `--mode smoke|full|tables-only`
  - `--phase phase1|phase2|linear|all`
  - `--assets`
  - `--models`
  - `--seed`
  - `--outdir`
  - `--skip-existing`
  - `--force`
  - `--reuse-prior-baselines`
- Keep smoke, reused-prior, skipped-existing, scaffolded, failed, and current generated model provenance explicit.
- Exclude smoke and reused-prior rows from paper tables by default.
- Use deterministic seeds for random residues, shuffled PM, and random gates.
- Use no global standardization for OPS/shape/gate features. Standardized shape features use prior-row expanding statistics so each transformed row is computed only from information available before that row.
- Use fixed ridge penalties and fixed logistic gate defaults in the first implementation. Do not aggressively tune gates or penalties.

## Validation Policy

- Do not rerun full existing CP/raw PM/raw CP+PM tests during implementation.
- Reuse saved HAR/CP/PM predictions for reference when requested with `--reuse-prior-baselines`.
- Raw CP+PM timestamp forecasts are regenerated by the new runner because the previous incremental output does not store timestamp-level hybrid predictions.
- During implementation, run at most one quick smoke run per model.
- `SUCCESS.txt` is written only after required output files are present and all generated OPS/shape feature zero-block-sum checks pass.

## Commands

Smoke test:

```powershell
python outputs/cp_ops_hg_tests/scripts/run_cp_ops_hg_tests.py --mode smoke --assets AAPL --phase all --seed 42 --force
```

Phase 1:

```powershell
python outputs/cp_ops_hg_tests/scripts/run_cp_ops_hg_tests.py --mode full --phase phase1 --seed 42 --skip-existing
```

Phase 2 / full linear ladder:

```powershell
python outputs/cp_ops_hg_tests/scripts/run_cp_ops_hg_tests.py --mode full --phase linear --seed 42 --skip-existing
```

Final all-model full run:

```powershell
python outputs/cp_ops_hg_tests/scripts/run_cp_ops_hg_tests.py --mode full --phase all --seed 42 --skip-existing
```

Regenerate tables from existing outputs:

```powershell
python outputs/cp_ops_hg_tests/scripts/run_cp_ops_hg_tests.py --mode tables-only --outdir outputs/cp_ops_hg_tests
```

## Acceptance Criteria

- The runner can complete a smoke test on one asset.
- The runner exposes all required CLI options.
- The full model spectrum is implemented, with CP-OPS-K either implemented or explicitly scaffolded in metadata and README.
- Fresh CP, raw PM, and raw CP+PM can be compared against prior outputs for validation/reference.
- Every model compares against fresh CP on identical rows.
- Every OPS/shape feature passes the zero-block-sum check for each fallback CP block.
- Placebo models are deterministic.
- Smoke/reused/skipped/generated statuses are visible in `run_metadata.csv`.
- Paper tables exclude smoke and reused-prior rows by default.
- README includes the locked interpretation rules.
